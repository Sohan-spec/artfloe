## PART A — FOUNDATION

### A.1 Auth Strategy: JWT (Supabase-native), not server-side sessions

**Decision:** Use Supabase Auth's native JWT access-token + refresh-token model. Do **not** build a custom Flask session store (no `Flask-Login`, no Redis session backend).

**Why this decision, specifically for your architecture:**

Supabase Auth's own documentation states the reasoning plainly: *"Supabase Auth prefers a JWT-based approach using access and refresh tokens because session information is encoded within the short-lived access token, enabling"* stateless verification, versus a traditional session-string approach where *"if the authentication server or its database crashes or is unavailable for even a few seconds, the whole application goes down"* and *"all requests that require authentication has to be routed through the authentication [server], which adds an additional latency overhead to all requests"* (supabase.com/docs/guides/auth/sessions).

This matters more for ArtFloe than for a typical app because **your compute is split across two separate serverless tiers** — a Flask WSGI container and a separate Modal GPU container (per `SYSTEM_ARCHITECTURE.md` section 2). A cookie-session approach would require a shared session store (Redis) reachable from both tiers, adding a new stateful dependency to an otherwise stateless serverless architecture. A JWT is self-contained: the GPU worker (or any other Modal function) can verify the token locally against Supabase's JWKS public key without a round-trip to a session store, which fits the *"serverless / edge environment where keeping a session store in the hot path is awkward"* case that current guidance explicitly calls out as the scenario favoring JWT (rune.codes, May 2026).

**The concrete pattern (per Supabase's own recommended flow, and matching the browser-security consensus in 2026 guidance):**
- Access token: short-lived JWT (default 1 hour), sent as `Authorization: Bearer <token>` header on API calls — never stored in `localStorage`
- Refresh token: long-lived, stored in an **HttpOnly, Secure, SameSite=Strict cookie**, scoped to the token-refresh endpoint only
- This is the same pattern independently converged on by Auth0/Clerk/Supabase per 2026 guidance: *"The access token lives in a JavaScript variable... The refresh token sits in an HttpOnly, Secure, SameSite cookie... XSS can't dump the access token from localStorage (it isn't there) and can't read the refresh token at all"* (crosscheck.cloud, May 2026)
- On logout, Supabase deletes the row from `auth.sessions` — your Flask backend doesn't need to track revocation itself; a JWT `session_id` claim check against `auth.sessions` is sufficient if you need mid-lifetime revocation checks

**What this means for Flask implementation specifically:**

```python
# requirements.txt additions
# supabase==2.x
# pyjwt==2.x

# auth/verify.py
import jwt
import os
from functools import wraps
from flask import request, jsonify, g

SUPABASE_JWT_SECRET = os.environ["SUPABASE_JWT_SECRET"]  # from Supabase project settings

def verify_token(token: str) -> dict:
    """Stateless verification — no network call to Supabase needed per-request."""
    return jwt.decode(
        token,
        SUPABASE_JWT_SECRET,
        algorithms=["HS256"],
        audience="authenticated",
    )

def require_auth(f):
    @wraps(f)
    def wrapper(*args, **kwargs):
        auth_header = request.headers.get("Authorization", "")
        if not auth_header.startswith("Bearer "):
            return jsonify({"error": "missing_token"}), 401
        token = auth_header.split(" ", 1)[1]
        try:
            payload = verify_token(token)
        except jwt.ExpiredSignatureError:
            return jsonify({"error": "token_expired"}), 401
        except jwt.InvalidTokenError:
            return jsonify({"error": "invalid_token"}), 401
        g.user_id = payload["sub"]
        g.user_email = payload.get("email")
        return f(*args, **kwargs)
    return wrapper
```

### A.3 Storage Architecture (Supabase Storage + Modal Volume)

**Decision:** Supabase Storage becomes the source of truth for user-facing files (content uploads, style uploads, final outputs). The Modal Volume remains the GPU worker's fast local scratch space during a single generation, then the result is pushed to Supabase Storage at the end. This directly fixes the filename-collision bug already found in your dev log.

**Bucket layout:**
```
content-uploads/{user_id}/{generation_id}.{ext}
style-uploads/{user_id}/{style_id}.{ext}          -- custom user styles
outputs/{user_id}/{generation_id}.jpg
outputs/{user_id}/{generation_id}_4k.jpg          -- upscaled variant, written on demand
outputs/{user_id}/{generation_id}_timelapse.mp4
```

### A.4 Content Moderation (NudeNet, self-hosted)

**Decision recap:** self-hosted NudeNet, gated before any paid GPU work runs. Runs on CPU — do not schedule it on the A10G GPU function, it doesn't need one and doing so would waste GPU-seconds you're paying for.

```python
# modal_app.py additions

    modal.Image.debian_slim()
    .pip_install("nudenet", "opencv-python-headless")
)

@app.function(image=moderation_image, cpu=1.0)
def moderate_image(image_bytes: bytes) -> dict:
    from nudenet import NudeDetector
    import tempfile

    detector = NudeDetector()
    with tempfile.NamedTemporaryFile(suffix=".jpg") as tmp:
        tmp.write(image_bytes)
        tmp.flush()
        results = detector.detect(tmp.name)

    # NudeNet returns per-region labels with confidence; flag on any exposed-category hit above threshold
    flagged_classes = {"EXPOSED_BREAST_F", "EXPOSED_GENITALIA_F", "EXPOSED_GENITALIA_M", "EXPOSED_BUTTOCKS"}
    hits = [r for r in results if r["class"] in flagged_classes and r["score"] > 0.6]

    return {"flagged": len(hits) > 0, "max_score": max([h["score"] for h in hits], default=0.0)}
```

### B.1 Subtle Subject Stylization

**File touched:** `utils/utils.py`, `neural_style_transfer.py`, `app.py` (new query param)

**Current behavior (per architecture doc §4.4):**
```
I_final = α · I_original + (1 - α) · I_stylized
```
with α = 1.0 (full binary preservation) wherever the person mask applies.

**New behavior:**
```python
# utils/utils.py — save_and_maybe_display()
def save_and_maybe_display(optimizing_img, config, ...):
    ...
    if config.get("enable_person_preserve") and config.get("person_mask_float") is not None:
        alpha = config["person_mask_float"]  # existing feathered mask, values in [0,1]

        # up to 0.10-0.15 = subtly stylized so the subject reads as part of the painted scene
        subject_blend_strength = config.get("subject_blend_strength", 0.0)

    ...
```

### B.2 Per-Style Color Grading (3D LUT)

**New file:** `utils/color_grading.py`
**New dependency:** none beyond what's already in `modal_app.py` (`kornia`, `opencv-python`)
**New assets:** one `.cube` LUT file per named style, stored alongside style images

```python
# utils/color_grading.py
import cv2
import numpy as np

def load_cube_lut(path: str) -> np.ndarray:
    """Parses a standard .cube 3D LUT file into a lookup array."""
    size = None
    data = []
    with open(path) as f:
        for line in f:
            line = line.strip()
            if line.startswith("LUT_3D_SIZE"):
                size = int(line.split()[-1])
            elif line and not line.startswith(("#", "TITLE", "DOMAIN")):
                parts = line.split()
                if len(parts) == 3:
                    data.append([float(x) for x in parts])
    lut = np.array(data, dtype=np.float32).reshape((size, size, size, 3))
    return lut

def apply_lut(image_rgb_uint8: np.ndarray, lut: np.ndarray, strength: float = 0.6) -> np.ndarray:
    """Applies a 3D LUT via trilinear interpolation, blended at `strength`."""
    size = lut.shape[0]
    img_float = image_rgb_uint8.astype(np.float32) / 255.0
    idx = (img_float * (size - 1)).astype(np.int32)
    idx = np.clip(idx, 0, size - 1)
    graded = lut[idx[..., 0], idx[..., 1], idx[..., 2]]
    graded_uint8 = (graded * 255.0).astype(np.uint8)
    blended = cv2.addWeighted(graded_uint8, strength, image_rgb_uint8, 1 - strength, 0)
    return blended

def apply_lut_to_masked_region(image_rgb_uint8, lut, alpha_mask, strength: float = 0.6):
    """Grades only within the person-alpha-mask region (feathered), leaves background untouched
    (background is already the stylized NST output, doesn't need this)."""
    graded_full = apply_lut(image_rgb_uint8, lut, strength)
    alpha_3ch = np.stack([alpha_mask] * 3, axis=-1)
    return (alpha_3ch * graded_full + (1 - alpha_3ch) * image_rgb_uint8).astype(np.uint8)
```

**Integration point in `utils/utils.py`:**
```python

    lut = load_cube_lut(config["style_lut_path"])
    final_img = apply_lut_to_masked_region(
        final_img, lut, config["person_mask_float"], strength=config.get("lut_strength", 0.6)
    )
```

**LUT authoring:** author once per named style (see Part E, style catalog). No model training — a colorist can produce `.cube` files in DaVinci Resolve (free tier) or they can be generated programmatically from target-color specs (e.g., `cool_shadows_purple_highlights.cube` for "Dreamy"). Per current LUT-grading guidance, start blend strength around 50–70% and compare against the ungraded result rather than defaulting to 100% (aaapresets.com, June 2026) — the `strength=0.6` default above reflects that.

**Testing checklist:** run against at least 5 style/content pairs spanning different skin tones and lighting conditions before shipping default-on; this is a visible, user-facing change to every photo with a person in it.

**New Modal function**, kept separate from the main NST GPU function so it can be invoked independently and billed/gated independently later.

```python
@app.function(image=upscale_image, gpu="A10G", volumes={"/data": volume})

    from basicsr.archs.rrdbnet_arch import RRDBNet

    input_path = f"/data/output-images/{generation_id}.jpg"
    output_path = f"/data/output-images/{generation_id}_upscaled.jpg"

    model = RRDBNet(num_in_ch=3, num_out_ch=3, num_feat=64, num_block=23, num_grow_ch=32, scale=4)
    upsampler = RealESRGANer(

        half=True,       # fp16, faster on A10G
```

```python
@require_auth
def upscale(generation_id):

    if not row.data or row.data["status"] != "complete":
```

**Why `tile=400` and `half=True`:** tiling is the standard mitigation for VRAM blowup on large images with Real-ESRGAN — current guidance is explicit that *"the model is small; the output resolution is what eats memory — use tiling... to keep large outputs within VRAM"* (localaimaster.com, June 2026). `half=True` (fp16) roughly halves memory and speeds inference on your A10G with negligible quality loss, consistent with the fp16 usage pattern already established elsewhere in your stack (RMBG-2.0 inference).

### C.3 Style Strength Slider

**Decision (from previous discussion, now specified concretely):** precomputed discrete presets along the α/β interpolation curve, not live re-optimization per slider tick — avoids re-running 600 LBFGS iterations per UI interaction.

```python
# neural_style_transfer.py — precompute at generation time, not per slider move
STRENGTH_PRESETS = {
    # (content_weight_multiplier, style_weight_multiplier) — tuned around your existing defaults
    # α=1e5, β=300 (per SYSTEM_ARCHITECTURE.md §4.3)
    10:  (1.4, 0.4),
    30:  (1.2, 0.7),
    50:  (1.0, 1.0),   # existing default ratio
    70:  (0.8, 1.4),
    90:  (0.6, 1.9),
    100: (0.5, 2.2),
}

def resolve_strength_weights(strength_pct: int, base_alpha=1e5, base_beta=300):
    nearest = min(STRENGTH_PRESETS.keys(), key=lambda k: abs(k - strength_pct))
    c_mult, s_mult = STRENGTH_PRESETS[nearest]
    return base_alpha * c_mult, base_beta * s_mult
```

```python
# app.py
style_strength = int(request.args.get("style_strength", 50))
alpha, beta = resolve_strength_weights(style_strength)
config["content_weight"] = alpha
config["style_weight"] = beta
```

This still runs a full LBFGS optimization per generation (same cost as today), it just changes which weight preset is used — the "instant slider feel" tradeoff is that changing strength requires re-generating, same as changing style does today. If true live-preview strength adjustment is wanted later, the cheaper (but architecturally distinct) alternative is post-hoc compositing between the generated output and the original content image at a chosen blend ratio — flagged as a future option, not built here, since it doesn't actually change the optimization the way a real strength control should.

### D.1 Preserve Additional Objects (SAM 3)

**New Modal function**, parallel to the existing Faster R-CNN + RMBG-2.0 pipeline — this is additive, not a replacement of the default person-preservation path.

```python
# modal_app.py additions

        "Sam3Model.from_pretrained('facebook/sam3'); Sam3Processor.from_pretrained('facebook/sam3')\""
    )
)

@app.function(image=sam3_image, gpu="A10G", secrets=[modal.Secret.from_name("hf-secret")])
def segment_by_prompt(image_bytes: bytes, prompt: str) -> dict:
    """Returns a feathered alpha mask for every instance matching the text prompt,
    e.g. prompt='dog' or prompt='car' or prompt='person'."""
    from transformers import Sam3Model, Sam3Processor
    from PIL import Image
    import io, torch, numpy as np, cv2

    model = Sam3Model.from_pretrained("facebook/sam3").to("cuda")
    processor = Sam3Processor.from_pretrained("facebook/sam3")

    image = Image.open(io.BytesIO(image_bytes)).convert("RGB")
    inputs = processor(images=image, text=prompt, return_tensors="pt").to("cuda")

    with torch.no_grad():
        outputs = model(**inputs)

    # presence_token tells you whether the concept exists in the image at all —
    # check it before trusting the mask, per SAM3's documented design
    if outputs.presence_score.item() < 0.5:
        return {"found": False, "mask": None}

    mask = processor.post_process_masks(outputs, inputs["original_sizes"])[0]
    mask_np = mask.cpu().numpy().astype(np.float32)
    feathered = cv2.GaussianBlur(mask_np, (0, 0), sigmaX=21)  # same feather_radius=21 already used for RMBG

    return {"found": True, "mask": feathered.tolist()}
```

**Why gated behind `presence_score`:** SAM 3's own design includes a presence token specifically to avoid hallucinating a mask when the prompted concept isn't in the image — this is the mechanism that lets you safely expose a free-text prompt field to users without silently returning garbage masks on a miss (per SAM 3 paper, arxiv.org/html/2511.16719v1, "a presence token that first checks whether the concept exists in the image at all").

### D.2 Style Mixing

```python
# neural_style_transfer.py — extend the style loss computation
def compute_style_loss(current_features, style1_targets, style2_targets=None, mix_ratio=1.0):
    """mix_ratio=1.0 means 100% style1 (current single-style behavior, default).
    mix_ratio=0.6 means 60% style1 / 40% style2."""
    loss1 = sum(
        torch.nn.functional.mse_loss(gram_matrix(cf), gram_matrix(t1))
        for cf, t1 in zip(current_features, style1_targets)
    )
    if style2_targets is None:
        return loss1

    loss2 = sum(
        torch.nn.functional.mse_loss(gram_matrix(cf), gram_matrix(t2))
        for cf, t2 in zip(current_features, style2_targets)
    )
    return mix_ratio * loss1 + (1 - mix_ratio) * loss2
```

### E.2 Smart Cropping

```python
# utils/utils.py
CROP_RATIOS = {
    "square_1_1": (1, 1),
    "portrait_4_5": (4, 5),
    "story_9_16": (9, 16),
    "wallpaper_16_9": (16, 9),
}

def smart_crop(image, person_bbox, ratio_key):
    """Crops to the given aspect ratio, centered on the person bounding box when present,
    else centered on the image."""
    target_w, target_h = CROP_RATIOS[ratio_key]
    img_h, img_w = image.shape[:2]
    target_aspect = target_w / target_h

    if person_bbox:
        cx = (person_bbox[0] + person_bbox[2]) / 2
        cy = (person_bbox[1] + person_bbox[3]) / 2
    else:
        cx, cy = img_w / 2, img_h / 2

    if img_w / img_h > target_aspect:
        crop_h = img_h
        crop_w = int(crop_h * target_aspect)
    else:
        crop_w = img_w
        crop_h = int(crop_w / target_aspect)

    x1 = int(max(0, min(cx - crop_w / 2, img_w - crop_w)))
    y1 = int(max(0, min(cy - crop_h / 2, img_h - crop_h)))
    return image[y1:y1 + crop_h, x1:x1 + crop_w]
```


Deterministic, no model call, reuses the bounding box Faster R-CNN already computed during generation (store it in `generations.params` at generation time so cropping doesn't need to re-run detection).
